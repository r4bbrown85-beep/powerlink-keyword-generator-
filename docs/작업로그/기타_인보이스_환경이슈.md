## 2. 구글 전자세금계산서 — 메일에서 금액을 못 읽는다

Outlook `구글인보이스` 폴더(팀장이 2026-10-05에 `구글@`에서 옮겨둠)에 구글 발행 전자세금계산서 알림 메일이 누적돼 있다.

**이 메일 본문에는 금액이 없다.** 발행 사실·공급자/공급받는자·승인번호 수준의 알림만 들어 있고, 공급가액/세액/합계는 전자세금계산서 본문(홈택스) 또는 첨부에만 있다. → **Outlook COM으로 본문을 긁어 금액을 집계하는 접근은 불가능**(2026-10-05 실측).

금액이 필요하면 (1) 첨부 PDF/XML 확인 → (2) 홈택스 기간 조회(팀장/재무팀) → (3) 매체별 월 정산이면 애초에 사내 인보이스 마스터 파일이 소스.

## 3. 열어둔 탐색기 폴더가 전부 닫히는 현상 — 내 작업이 원인이 아니다

팀장 지적: *"폴더 경로 지정해서 작업시키면 열어놨던 탐색기 폴더가 전부 닫혀버린다."*

이벤트 로그(`Get-WinEvent`, Application Error 1000) 검증 결과:

| 항목 | 값 |
|---|---|
| 최근 30일 `explorer.exe` 크래시 | **15회** |
| 결함 모듈 | `ntdll.dll` 12회(`0xc0000374` 힙 손상), `unknown` 1회(`0xc0000409`), `SHELL32.dll` 2회 |
| 당일 크래시 시각 | **08:58 / 09:10** — 내가 네트워크 폴더 작업을 한 저녁 시간대와 전혀 겹치지 않음 |

**→ 내 스크립트가 원인이 아니다.** win32com/파일 읽기는 explorer 프로세스를 건드리지 않는다. explorer가 죽으면 열려 있던 모든 폴더 창이 함께 사라지고 자동 재시작되므로 "갑자기 다 닫혔다"는 체감과 정확히 일치한다.

**의심 지점**: 사내 보안 에이전트 DLL(`BMSMMDrv_x64.dll`, `BMSys_x64.dll`, `BMServ2Dll_x64.dll`) 및 `C:\Program Files\WinUpdateRecovery\BMSIASServ3_x64.exe`. explorer.exe에 인젝션되는 구조라 힙 손상 크래시의 전형적 원인 후보.

**근본 해결은 정보보호팀 에스컬레이션**(보안 에이전트 버전 문제) — 내가 고칠 수 있는 범위가 아니다. 완화책으로 "폴더 옵션 → 별도 프로세스로 폴더 창 실행(SeparateProcess)" 설정이 있다.

같은 계열의 환경 이슈: DRM 폴더 파일을 PDF/복사 저장하면 SCDSA 자체 컨테이너로 감싸져 표준 도구로 검증이 안 되는 현상.
