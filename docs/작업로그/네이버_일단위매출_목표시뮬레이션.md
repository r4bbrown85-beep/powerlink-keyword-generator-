#### DRM 래핑 CSV 처리 (2026-10-06 확인)
`read_4213_csv()`가 머리 8바이트의 `SCDSA004`를 보고 분기한다. 실측: **09/30·10월분은 평문, 06~08월분과 09/29분은 DRM 래핑**.

**Excel SaveAs로 평문 복사본을 뜨는 방법은 쓸 수 없다** — 사내 DRM이 저장 산출물을 SCDSA 컨테이너로 **다시 감싸버려서** 복사본도 평문이 아니다(실측 확인). 그래서 `_read_via_excel()`이 헤더로 열 위치를 찾아 **필요한 17개 열만 열 단위로 COM 읽기**를 한다(8월 58,160행 기준 8.3초).

추가 함정: Excel COM이 돌려주는 날짜는 pywintypes 객체인데 `tzinfo.utcoffset()`이 None이라 `pd.to_datetime`에 그대로 넘기면 `'NoneType' object has no attribute 'total_seconds'`로 터진다 → 직접 포맷해야 한다.

## 2. 월 목표 → 일별 시나리오 시뮬레이터

**모듈**: `agent/naver_target_simulator.py`


산출물: `...\네이버 일단위 매출 트래킹\네이버_YYYY-MM_일별목표_MMDD기준.xlsx`

월 중간에 다시 돌리면 그때까지 실적을 반영해 잔여일 필요액을 재배분한다(`as_of` 자동 감지).

### 추적·재보정
```python
sim.evaluate()         # 기록된 예측 vs 실적 채점
```

### 일별 배분 방식은 실측으로 결정했다 (바꾸려면 재검증 먼저)

일별 점유율 예측 오차(MAE, bp — 낮을수록 정확):

| 방식 | GFA | SA |
|---|---|---|
| **균등** | **38.4** | 25.2 |
| 공휴일 보정 | 38.4 | 25.5 |
| **공휴일+요일** | 38.5 | **23.0** |
| 전년 동월 형태 | 42.7 | — |
| 전체월 평균 형태 | 37.6 | — |

→ **GFA = 균등 배분, SA = 요일지수 × 공휴일계수**로 확정.
SA 요일지수: 일 1.068 / 월 1.057 / 금 0.924(쇼핑검색 주말 수요). SA 공휴일계수 1.063.

**월내 형태(상순 0.948 / 하순 1.051)를 GFA 배분에 쓰면 안 된다.** 그 경향은 세일이 있던 달(3·6·10월) 평균일 뿐이고 2025-11은 상순 1.089 > 하순 0.984, 2025-12는 중순이 최고로 **월별로 방향이 뒤집힌다.** 2026-10-05에 이 방식으로 만들었다가 검증 후 폐기했다.

### 쓰지 않기로 한 것
- **요일·월내·공휴일 완전분해 모델**: `revenue_forecast.py` 백테스트에서 MAPE 11.56% vs 단순 최근7일 9.47%로 **열등**.

- **기대수수료(목표×요율×확률)**: 2026-10-05에 제시했다가 팀장이 *"추가 수수료는 목표를 달성해야 주는 것"*이라고 지적. **전액 아니면 0원인 구조에서 확률 가중 기대값은 혼란만 준다. 쓰지 말 것.** 대신 **"구간별 필요 일평균 + 현재 대비 상향폭"**으로 비교한다.
